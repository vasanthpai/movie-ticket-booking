# Troubleshooting

Real problems hit during development, and how they were solved.

---

## `Port 5000 is already in use`

**Cause:** another process (often a previous `npm run dev` still running in another
terminal) is already listening on the port.

**Fix:** stop the other process, or change `PORT` in `backend/.env`.

On Windows, find what's using the port:
```powershell
netstat -ano | findstr :5000
taskkill /PID <pid> /F
```

---

## `❌ Invalid environment variables` on startup

**Cause:** a value in `backend/.env` doesn't match the schema in
`backend/src/config/env.ts` (e.g. `PORT=abc`).

**Fix:** the message names the variable — correct it in `.env`. Compare against
`.env.example`.

---

## npm warns: `esbuild ... install scripts not yet covered by allowScripts`

**Cause:** npm 11 doesn't run dependencies' install scripts unless you approve them.
This protects against malicious packages that run code during `npm install`.
`esbuild` (used by `tsx`) has one.

The frontend has the same warning for `unrs-resolver` (used by ESLint's import
plugin).

**Status:** safe to ignore. esbuild ships its Windows/Linux/macOS binaries as
separate optional packages, so `tsx` works without the script. If `npm run dev` ever
fails with an esbuild error, run `npm approve-scripts esbuild` and reinstall.

---

## Git warns: `LF will be replaced by CRLF`

**Cause:** Windows uses CRLF line endings, Linux/macOS use LF. Without a rule, Git
converts them, and the same file can look different on different machines.

**Fix:** the root `.gitattributes` sets `* text=auto eol=lf`, and Prettier uses
`"endOfLine": "lf"`, so every file uses LF everywhere.

---

## Font never applies (falls back to the browser default)

**Cause:** after `shadcn init`, `app/globals.css` contained
`--font-sans: var(--font-sans);`, a variable that refers to itself. CSS treats a
circular reference as invalid, so the font declaration is thrown away.

**Fix:** point it at the variable `next/font` defines in `app/layout.tsx`:
`--font-sans: var(--font-geist-sans);`

---

## `.env.example` isn't committed in `frontend/`

**Cause:** the `.gitignore` generated by `create-next-app` ignores `.env*`, which
also matches `.env.example`.

**Fix:** add `!.env.example` right after it. The `!` re-includes a file that an
earlier pattern excluded. Check with `git add -n frontend`.

---

## `Missing environment variable NEXT_PUBLIC_API_URL`

**Cause:** `frontend/.env.local` doesn't exist or doesn't define the variable.

**Fix:** `cp .env.example .env.local`, then **restart** `npm run dev`. Next.js reads
env files only at startup.

---

## `Could not connect to MongoDB` on startup

The server refuses to start without a database. Common causes:

| Message contains                       | Likely cause / fix                                                      |
|----------------------------------------|--------------------------------------------------------------------------|
| `bad auth` / `Authentication failed`   | Wrong username or password in `MONGODB_URI`, or special characters not URL-encoded |
| `Server selection timed out` / `ENOTFOUND` | Your IP isn't in Atlas **Network Access**, or the cluster hostname is wrong |
| `ECONNREFUSED 127.0.0.1:27017`         | Local MongoDB isn't running                                              |

Data ends up in a database called `test`? You left the database name out of the
URI. See `database.md`.

---

## Requests with a bad body don't show up in the request log

**Cause:** middleware order. If `morgan` is registered *after* `express.json()`, a
request with invalid JSON is rejected by the parser before it reaches the logger.

**Fix:** register `morgan` before `express.json()`. (Found and fixed in Phase 2.)
